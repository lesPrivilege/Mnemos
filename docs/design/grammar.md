## 一、对象与共同语法

共同顺序为：**对象与事实 → 读态 / 操作 → 组件解剖 → 形、材质、图标、动效**。沿用 CW 的分层，但 owner 改为 Mnemos 的文档、高亮、卡片、题目、会话与本地存储。

对象身份不随样式或所在页面改变。Document、Highlight、Card、Question、Deck、LearningPlan、ActivityEntry 是本包使用的概念名，不要求以这些英文名重命名现有数据结构。

读态只回答材料是什么、来自哪里、现在处于什么状态。操作回答能做什么、作用于什么、何时写入、如何取消与恢复。展现层不能把滚动百分比升级为掌握率，也不能让拖拽动作改写复习到期时间。

四个统一动词：**展开、选择、提交、返回**。放大／翻面是展开的一种表现；拖拽是选择或移动的一种表现；动画结束不是提交；关闭一个来源面不等于离开当前任务。

可选项不阻塞首个学习闭环。每个 grammar 最多一份主实现，移动与宽屏只改变布置，不复制状态机。

## 三、代表场景的状态合同

### 3.1 选区与制卡

`reading → selection → excerpt/draft → editing → saving → saved | failed`

选区到 editing 之前复制必要的 quote、range 定位与 return context，不能把一个将被 DOM 更新破坏的 Range 对象当作持久来源。selection、draft、saved 是三个对象阶段，不以 CSS class 替代。

保存摘录后不强制打开大面板；用户保持在原文。制卡时允许编辑问题与答案，现有 `note → front / selectedText → back` 只是预填先例，不自动猜题。取消尚未保存的草稿不删除原摘录；失败保留文本与目标。

现有 Reader 的制卡路径写入 `front/back/type/chapter/section` 并通过路由状态进入 Import；来源标题只是答案中的文本。新增关联必须在 Import 分配真实 cardId 后绑定。不能使用标题、数组下标或临时预填 ID 当永久标识。

建议最小 `SourceLinkV1` 候选：

```ts
type SourceLinkV1 = {
  version: 1;
  target: { kind: 'card'; id: string };
  source: {
    kind: 'document' | 'question';
    id: string;
    highlightId?: string;
    quote: string;
    textOffset?: number;
    length?: number;
    contextBefore?: string;
    contextAfter?: string;
    contentFingerprint?: string;
  };
  createdAt: string;
};
```

这是候选新增合同，不是现行字段清单。首片只实现 document/highlight 分支；question 分支与错题入口一起消费。沿现有 `highlightAnchor` 机制扩展：精确定位失败后可搜索 quote+上下文；多个候选不得静默当精确命中。fingerprint 的输入必须明确定义，不能混用原始 Markdown 与渲染后文本。

新关联如需持久化，应进入既有备份/恢复流程；旧备份没有该字段仍能导入。禁止只把新字段塞进路由 state 后宣布跨启动可用。创建卡片与保存关联的失败必须分别可见；没有跨存储事务时，优先使用明确的补偿/重试回执，而非假装两步原子成功。已被复习或编辑的卡片不能因为旧“撤销制卡”回执而被静默删除。

### 3.2 复习与撤销

常规路径：`front → answer → commit → receipt/next`。可选手势预览路径：`answer → rating-preview → commit → receipt/next`。前者不增加额外确认。

`undo` 回到前一张 `answer`，恢复的集合至少包含原 SM-2 状态、learning passes、requeue 位置与本次统计。现有 `Review.jsx` 已保存部分相关前态；施工先读完整 handler 和 undo 路径，不只修改卡片外观。

质量枚举是 `1 / 2 / 4 / 5`。新增评价轨只重组这些离散动作，不发明连续值。未见答案不评分；预览不记录事件；提交只执行一次。学习卡重排后，“完成 N 项”与“处理 N 次”分别计算，不能用固定初始队列长度美化进度。

评分按钮、快捷键、手势预选后的确认必须汇入同一受保护 action，防止一次输入触发两次提交；预选通道的 drag end 不直接写入。animationend、onAnimationComplete 不持有存储写权。撤销动画表现已完成的恢复，不承担恢复本身。

### 3.3 本次学习托盘

候选最小结构为 `planId / ordered typed refs / cursor / updatedAt`。它描述本次先看什么，不修改 card due。资料被删除时保留失效条目与“移除”动作，不把下一项错认成它。

第一次仅支持条目增删、排序、继续，不增加跨天排程、自动学习规划或跨端同步。资料列表多选与托盘拖拽有独立 handle，不能让整行长按同时触发文本选择、多选与拖拽。

### 3.4 返回、层级与生命周期

同一时刻最多一个 modal。小型 context popover 可以 non-modal，但不能在 modal 外留下可操作的假背景。Android Back、Esc、关闭按钮按一致顺序退层：最上层浮层→当前局部编辑→当前对象→一级入口。未提交输入依其真实保存状态处理，不能为了顺滑而丢弃。

返回记录保存对象 ID、路由、结构锚点/offset、focus target 与必要的展开态；DOM 节点引用不进入持久存储。返回恢复不抢正在操作的焦点；目标已不存在时落到最近有效父级。来源 peek 不默认产生一次新的学习完成事件；单纯查看出处和启动新阅读会话分开。

## 四、动效谱

### 4.1 一套时间与节奏

| Motion 角色 | 首轮沿用底本 | 适用 | 不适用 |
|---|---|---|---|
| Immediate | 直接跟随输入 | 拖拽预览、选区与数值预览 | 人为加滞后追手 |
| Quick | `--motion-quick` 120ms | 按压、勾选、轻反馈 | 整屏进场 |
| State | `--motion-mid` 180ms | 工具条、标签、选择指示 | 多条数据依次跳动 |
| Surface | `--motion-gentle` 240ms | 局部 sheet、peek、返回 | 锁住导航直至结束 |
| Object | `--motion-slow` 420ms 上限候选 | 一次对象转换的强 specimen | 每次高频评分强制播放满时长 |

当前标准曲线是 `cubic-bezier(0.2,0,0,1)`。这些是底本已有值，不是新的测量结果。共享运动的“更丰富”来自变形关系、起止位置与节奏，而不是把时长普遍加长。

一个主运动组内，选区、来源标记与目标卡可以协同变化；无关导航、背景图表保持静止。用户开始下一个动作时，立即接受新状态；旧转场可取消或从当前位置重定向。

### 4.2 六个可复用 recipe

| Recipe | 形与时机 | 中断 / 减弱动态 |
|---|---|---|
| Press → settle | 仅控件短暂内收，文本基线保持；松手恢复 | 取消手势立即恢复；减弱动态保留明确选中/按下态 |
| Selection → action | 依实际避碰方向从选区附近显现，不遮系统选择柄 | 选区变化重定位；失效即收起；减弱动态直接显示 |
| Quote → card | 选区身份/对象轮廓连续，编辑文字以完整尺寸呈现 | 取消回到原文；文字不参加 scale；减弱动态直接换面 |
| Answer → judgment | 答案原位展开，评价轨随后可用；无伪延迟 | 快速显答仍可立即评价；减弱动态直接呈现完整结构 |
| Commit → receipt | 动作区原位成为结果与撤销入口，下一项衔接 | 持久化失败停在可重试输入；重复触发不双写 |
| Lens → return | 来源从同一锚点打开并返回，恢复原位阅读 | 来源消失给出断链态；减弱动态保留层级与焦点关系 |

### 4.3 技术取舍

普通按压、状态与小浮层继续用 CSS。共享对象、连续重排和复杂跟手可做一个局部 Motion for React spike；Mnemos 已是 React，不继承 CW 原生 ES module 轨道的禁依赖条款。

Motion 官方支持 `layout` / `layoutId` 与基于 transform 的布局动画；它也可能拉伸子内容。阅读文本与公式优先位置转场或静态文本层，不以“用了 layout”当作排版完好的证据。显式设置 `MotionConfig reducedMotion="user"`；该选项的文档默认值是 `never`，不能靠默认配置。

不把 Motion、GSAP、多个 spring 引擎叠在一起。先比较 CSS 与一份 Motion slice 的实现复杂度、构建增量、打断行为与 WebView 实测。React Aria 只在需要高成本的拖拽、组合选择或浮层行为时定点采用；不是全量替换 UI。

native View Transitions 只作为页级增强候选，先做能力检测并保留无该 API 的路径；不为使用它升级 React、路由或 Capacitor，也不依赖 React 实验接口。

JS 与 CSS 使用同一动效来源。若采用 JS 动画，先在 `tokens.css` 把复合时长拆成基础 duration/easing 变量，原复合 token 作为兼容 alias；读取这些基础值或生成只读派生配置。不能在 JSX 手写另一套 0.12/0.18/0.24/0.42。

### 4.4 系统偏好与性能

减弱动态关闭位移、翻面、缩放与惯性演示，保留状态、焦点和可读回执。减少透明度、forced-colors 与 prefers-contrast 分开处理；不支持时以实底、可辨边界回退。CSS blur 不模拟平台原生玻璃。

长列表只作用于当前对象及邻近对象；不让整个文档、整张热图或所有卡片常驻动画布局测量。每次记录 bundle 增量、目标设备、交互片段与掉帧/长任务事实，再裁实现，不用桌面录屏代替 Android WebView 结果。

## 五、Shape／Material／Copy

圆角继续使用 `2 / 4 / 6 / 10px` 家族；pill 只给句柄、离散小标签或适当孤立控件。不得每加一种 grammar 就加一种圆角、按钮高度或图标族。

局部浮层的层次先由遮挡、实底与边界成立，再比较透明材料。禁动画 `backdrop-filter`；正文、选区与公式不 blur。拖拽对象可探索轻量抬升，但数据区不随 hover 浮起。

文案只说动作与结果：“摘录”“制成卡片”“显示答案”“查看原文”“加入本次学习”“撤销”“保存失败，重试”。设计名如 Source lens、Rating rail 不进入日常产品文字。删去重复的小标题、双语装饰、无意义统计与未产生行为的“智能”措辞。

同一类动作沿固定位置与语气；短标签不足以表达后果时，补充对象与影响，而不是用颜色代替说明。主操作不因强调而突然变成大红实心块。

## 六、验收矩阵

首轮测试宽度 390 与 834；最窄 320、横屏与 1440 为扩展矩阵。明暗、200% 文字、键盘、触屏、减弱动态、实底回退分别覆盖。设计目标为核心触控 ≥44px；触控可用与视觉图标大小分别记录。

每个 grammar 至少覆盖 resting、focus、active、selected、disabled/不适用、pending、success、error、cancel、return 中与它真实相关的状态。无异步动作的控件不凭空制造 pending。

关键反例：快速连续显答/评分；评分途中返回；保存失败后重试；选择后滚动；重复 quote；原文变更或删除；IME 输入；触屏长按选择；关闭再打开；没有数据/零数据；滚动未到底时新提示到达；样板刷新/重置后真实学习数据不变。

源码门禁、浏览器目验与真机行为分开记录。审校者没有亲自运行的项目不写 pass。样板录屏附开始状态、真实动作与结束状态，而非只截最好看的中间帧。
